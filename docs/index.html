01 / Architecture

One small process boundary

The agent names a capability. It never names a host, and it never holds the key. A macOS Keychain record or Linux password-encrypted age vault binds every route to its credential, its exact destination, and the capability policy that narrows it.

Agent-native capabilities

A Harness invokes named capabilities such as github-read, constrained by HTTP method, normalized path prefix, destination, and response size.

B

Existing applications too

For software that already reads a key from the environment, Towel hands the child a fake key and a loopback URL, then substitutes the real credential on the way out.

C

First integration: DeepSeek Harness

A twl_request tool owns one Towel child process through Harness lifecycle effects and contains no credential-resolution logic.

02 / Security boundary

Useful protection, precise claims

Towel keeps the reusable credential out of the agent. It does not make the authority behind that credential harmless: anything the granted capability can legitimately access is still available to the agent.

✓ Towel protects

  • The reusable credential from the agent process, its environment, and its descriptors
  • Trusted-store destinations from workspace edits and prompt injection
  • Method, path, and response bounds, enforced before any upstream request
  • Direct plaintext and common-Base64 key reflection

× Towel is not

  • A sandbox or general-purpose secret manager
  • A limit on what the granted capability can legitimately reach
  • Protection for the agent's own model login
  • Protection from an authorized upstream that transforms or exposes a key
03 / Try it safely

No real key required

The demo creates a canary credential and a local service, then runs the same application contract used by a real session. Nothing touches a real account. twl capability demo --stdio exercises the capability protocol the same way.

No account, no credential, no install — the demo generates both sides.

$ ./target/debug/twl demo \

04 / Install

Signed, notarized, verified

Prebuilt archives cover macOS (Apple Silicon and Intel) and Linux (x86-64 and ARM64). Linux binaries are statically linked against musl and run on any distribution with nothing else installed. macOS archives contain a Developer ID-signed, notarized and stapled TowelCLI.app, so Gatekeeper accepts it directly.

Every archive carries a build-provenance attestation — check it before you trust a security tool you downloaded.
Releases ↗ Download commands ↗

# Linux — download from the releases page, then
$ tar xzf twl-*-x86_64-unknown-linux-musl.tar.gz

A small literary nod

Why a towel?

Douglas Adams made the towel an icon of lightweight, improbable usefulness. This one is similarly unassuming: keep it beside your agent, put the dangerous credential behind it, and don't panic.
